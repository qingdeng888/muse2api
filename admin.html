方式一 · 浏览器扩展（推荐）

no terminal

浏览器扩展能把你自己电脑上已登录的 muse.ai 会话同步进来。无需 Python、无需命令行。
为什么必须用扩展：muse.ai 的登录会话 Cookie 标记了 httpOnly， 网页脚本（F12 里敲 document.cookie、书签脚本）读不到，只有浏览器扩展的 cookies API 能读。

⬇ 下载扩展包 (zip) 查看包内容 …
解压到一个不会删除的目录，例如 D:\muse2api-extension。
  • 地址栏输入 chrome://extensions 回车
  • 打开右上角开发者模式
  • 点击左上角加载已解压的扩展程序
  • 选择第 1 步解压出来的目录（不是里面的单个文件）
先在自己的浏览器打开 https://muse.ai/ 并登录（能看到聊天界面），再点击工具栏扩展图标， 填入下面两个值，点「读取并导入」。

方式二 · 手动复制 Cookie

F12 network

不想装扩展就手动复制 Cookie 字符串。关键是要用「网络」面板里的请求头，而不是 Console： 请求头里的 cookie: 一行包含 httpOnly Cookie，Console 读不到。

  1. 自己的浏览器打开并登录 https://muse.ai/，停在聊天界面
  2. 按 F12 打开开发者工具，切到「网络」面板
  3. 按 F5 刷新页面，让请求列表填满
  4. 点击列表里任意一个 muse.ai 请求（第一个就行）
  5. 右侧找到「标头」→ 下滑到「请求标头」
  6. 找到以 cookie: 开头的一行，复制冒号后面的完整字符串（从 hatch_sess= 到行尾）
  7. 粘贴到下面方式三的输入框，点「导入账号」

注意：要复制请求标头里的 cookie: 行，不是「响应标头」—— 响应标头里的 set-cookie 只有部分 Cookie，会缺。

          这三个就是 Muse 系列的真实能力：Muse Spark（语言 / 代码）、Muse Image（生图）、
          Muse Video（生视频）。muse.ai 网页是自动路由的 agent、界面没有模型选择器，
          所以 model 字段只用于兼容下游 —— 传 gpt-4o、
          claude-sonnet-4、dall-e-3 等常见名字会自动映射到对应能力。
        


        
2. 对话 / 写代码（curl）

        
chat · curl


# 非流式
curl -X POST "BASE/v1/chat/completions" \
  -H "Authorization: Bearer $MUSE2API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"muse-spark","messages":[{"role":"user","content":"写一个 Python 快排"}]}'

# 流式：加 "stream":true，返回标准 SSE（data: {...} / data: [DONE]）

        


        
3. 生图（curl）

        
images · curl


curl -X POST "BASE/v1/images/generations" \
  -H "Authorization: Bearer $MUSE2API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"一只戴宇航头盔的柴犬","size":"1:1","response_format":"url"}'

# 返回
{"created":1790148495,"data":[{
  "revised_prompt":"一只戴宇航头盔的柴犬",
  "url":"http://your-server:18610/v1/media/xxxx.webp",
  "kind":"image","bytes":23860}]

# url 是完整绝对地址，可直接给下游渲染 / 下载；/v1/media/* 无需鉴权。
# 想要 base64 就传 "response_format":"b64_json"。

        


        
4. 生视频（curl，异步）

        
videos · curl


# ① 创建任务
curl -X POST "BASE/v1/videos" \
  -H "Authorization: Bearer $MUSE2API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"海浪拍打礁石","duration":5,"size":"16:9"}'
# → {"id":"task_xxx","status":"queued",...}

# ② 轮询任务直到 completed（视频通常 60–120 秒）
curl "BASE/v1/videos/task_xxx" -H "Authorization: Bearer $MUSE2API_KEY"

        


        
5. openai Python SDK

        
python sdk


from openai import OpenAI

client = OpenAI(
    base_url="BASE/v1",
    api_key="你的API_KEY",
)

resp = client.chat.completions.create(
    model="muse-spark",
    messages=[{"role": "user", "content": "你好"}],
    stream=True,
)
for chunk in resp:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)

        


        
6. 鉴权说明

        

          除 /healthz、/readyz 和 /v1/media/* 外，所有接口都需要
          Authorization: Bearer <API Key>。API Key 由服务端 .env 的
          MUSE2API_KEY 配置。
        

        
7. 关于 tool_calls 的限制（重要，实测）

        

          muse.ai 网页助手有明确的对齐策略，拒绝输出「伪工具调用 JSON」。实测中它会回答「我不会按这种 JSON
          格式输出'伪工具调用'——我没有 get_weather 工具」。三种不同措辞与位置的提示协议均尝试失败。

          因此依赖 tool_calls 的自主 agent 模式（读写文件、执行命令等）无法支持；
          但所有问答式用法（对话、写代码、解释、翻译、总结、生图、生视频）完全可用。

          客户端即使传 tools 字段也不会报错：服务端忽略工具声明，按普通对话回答。

账号代理

    
绑定后，该账号与 muse 上游的所有通信（浏览器、会话检测、保活）都走所选代理。指定代理遇错自动转移到池内健康代理，恢复后自动回切；代理故障绝不静默直连。

    
    
    

      
      
      
没有合适的代理？先到「代理池」页添加并启用。

    

    
每次生成任务从池中取下一个健康代理；全部不健康时任务失败可见，绝不静默直连。
